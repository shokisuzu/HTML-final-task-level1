# チーム開発演習(Git/GitHub)　最終課題　レベル1

## 🗺️ TabiHub (タビハブ)
「日本の美しさを再発見し、共有するプラットフォーム」

## 🌟 プロジェクトの概要
TabiHubは、日本各地の観光スポットを「視覚的に」楽しみながら探し、ユーザー同士で情報を共有できる旅行系Webサイトです。
「次の旅先がすぐに見つかる」ことをコンセプトに、直感的な操作性とモダンなデザインを両立させました。

## 使用した主なBootstrapコンポーネント
標準機能を活用しつつ、CSSで独自にカスタマイズを行っています。
- Navbar (ナビゲーションバー): fixed-top と backdrop-filter: blur を組み合わせ、スクロールしても美しく、操作性を損なわないグラスモーフィズムデザインを採用。
- Card (カード): スポット一覧や掲示板で使用。hover 時に浮き上がるアニメーションを加え、クリックしやすさを向上。
- Grid System (グリッド): row と col を駆使し、PC・タブレット・スマホの全デバイスで最適なレイアウトに自動調整（レスポンシブ対応）。
- Badge (バッジ): ランキングの順位やスポットのカテゴリー（自然・グルメ等）を視覚的に分類。
- Buttons (ボタン): rounded-pill クラスを使い、柔らかい角丸デザインに統一。

## 工夫した点・オリジナル要素
本プロジェクト独自の「こだわり」ポイントです。
1. ビジュアル・ポディウム（ランキング表彰台）
- 通常のリスト形式ではなく、1位〜3位を直感的に伝える「表彰台（ポディウム）」レイアウトを独自実装しました。
 　Flexboxの order プロパティを使い、HTMLの構造を変えずに視覚的な順位を表現しています。
2. 吹き出し型コミュニティUI
- 掲示板セクションでは、チャットのような「吹き出し」スタイルを採用。
  従来の掲示板よりも親しみやすく、投稿のハードルを下げる工夫をしました。
3. 没入感のあるヒーローセクション
- clip-path を使用して背景画像を斜めに切り抜き、単調な四角いデザインにならないよう動的なレイアウトを実現しました。

## 📱 レスポンス対応について
- 完全レスポンシブ: Bootstrapのブレークポイントを活用し、スマホ閲覧時も画像や文字がはみ出さないように設計されています。
- スマホ専用メニュー: 画面幅が狭い場合はメニューを「ハンバーガーボタン」に集約し、コンテンツを主役にする設計です。

## 📂 サイト構成
- index.html：トップページ
- spot-list.html：スポット検索
- ranking.html：人気ランキング
- community.html：掲示板
- spot-detail.html：スポット詳細
- login.html / signup.html：ログイン・新規登録


## ルール
- 既存のページ構成・大まかなレイアウトは崩さず、オリジナルのWebサイトに書き換えること(`index.html`以外のファイル名の変更はしていいが、ページの削除はしないこと)
- 全体で最低5か所はレイアウトの一部を変更すること(Bootstrapを活用)
    - 色変更ではなく、配置や見え方を工夫すること
    - リンク先がない部分のページを増やすのは、レイアウト変更1つにカウント(ただし既存の別ページと全く同じレイアウトはNG)
    - どこを変更したか、を発表時に聞きますので、「忘れました」や「AIに作ってもらって解析していないので理解していません」ということの無いように
- レスポンシブレイアウトを維持すること(既存はレスポンシブ対応済み)
- 色・フォントは自由に変更可
- ファビコンをWebサイトの内容に合うよう変更すること(レイアウト変更にはカウントしません)
- クローン元のファイルでバグやレイアウト崩れを発見したら修正すること
- コードの可読性を意識すること
    - インデントを揃える
    - **意味のあるクラス名を付ける**
- 使われていないCSSなど、不要なコードを発見したら削除してOK
- Webサイトの概要が分かるREADME.mdを配置すること

## 補足
Issueを立てたり、タスク管理のツールでやらなければならないことを管理しておくと、抜け漏れがなく効率的に作業できると思います。  
また、README.mdに、使用したBootstrapコンポーネントや工夫した点、オリジナル要素をまとめておくと、発表時に説明しやすいかと思われます。

## 手順
1. 任意の場所にcloneする
2. リモートリポジトリをpublicで作成し、cloneしたリポジトリの接続先を、作成したリモートリポジトリに変更する
    ```bash
    git remote set-url origin 自分のリポジトリURL
    ```
3. 作業開始    
    適宜ブランチを切って、作業単位ごとにcommitするなど工夫して作業してください。  
    【ブランチ運用のメリット】
    - 作業内容を分けて管理できる
    - 誤ってmainを壊すリスクを減らせる
4. 作業終了後は、自分のリモートリポジトリにpushする
5. GitHub Pagesで公開する  
    [GitHub PagesでのWebサイト公開手順](https://prog-8.com/docs/github-pages)  
    上記手順の「5 ページの公開」を参考にしてください。
6. Classroomに公開したURLを提出
